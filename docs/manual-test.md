# BiliReader — чек-лист ручной проверки (baseline, фаза 0)

Проверяется **только чтение**: открытие EPUB/FB2, пагинация, темы, кегль, навигация,
сохранение прогресса. Перевод по выделению в этой сборке **отсутствует** — это фаза 1;
попап по выделению должен появиться, но перевода в нём не будет (см. проверку B10).

- Версия сборки: **0.12.16** (`apps/readest-app/package.json`)
- Платформа: Linux x86_64, рантайм CEF (не WebKitGTK)
- Артефакты: `target/release/bundle/{appimage,deb,rpm}/`
- Тестовые книги: `samples/` в корне репозитория

Ставьте отметку в колонке «Итог»: `OK`, `FAIL` или `—` (не проверялось).

## 1. Установка и запуск

### 1.1 AppImage (без установки)

```bash
cd target/release/bundle/appimage
chmod +x BiliReader_*.AppImage
./BiliReader_*.AppImage
```

- **Ожидаемо:** окно библиотеки появляется за 5–10 с, без диалога «нет прав» и без
  сообщений `panic` / `Traceback` в терминале.
- AppImage не требует root. Первый запуск может быть медленнее (распаковка в `/tmp`).
- Если окно не появилось: запустите из терминала и приложите его вывод к баг-репорту
  (см. §4). Проверьте, что `DISPLAY` указывает на рабочий X-сервер: `echo $DISPLAY`.

### 1.2 Debian/Ubuntu пакет

```bash
sudo apt install ./target/release/bundle/deb/BiliReader_0.12.16_amd64.deb
readest
```

- Пакет ставит `/usr/bin/readest` (имя исполняемого файла — `readest`, пакет — `bili-reader`).
- `apt install ./file.deb` (именно с `./`) сам подтянет зависимости из репозитория.
- Запуск также доступен из меню приложений (категория «Продуктивность»/«Офис»).
- Удаление: `sudo apt remove bilireader`.

### 1.3 RPM (Fedora/openSUSE)

```bash
sudo dnf install ./target/release/bundle/rpm/BiliReader-0.12.16-1.x86_64.rpm
readest
```

### 1.4 Dev-режим (из исходников)

```bash
scripts/bilireader-run.sh --cef   # приложение в окне, как в релизе
scripts/bilireader-run.sh         # только UI в браузере, http://localhost:3000
```

- Скрипт сам подхватывает nvm и rustup, проверяет системные библиотеки и печатает
  понятную причину, если чего-то не хватает.
- `--cef`: первый запуск 20+ минут (скачивается CEF и компилируется Rust), ~8 ГБ;
  дальше — секунды. `--desktop` — WebKitGTK, 10–15 минут и 2–3 ГБ.
- Остановка: `Ctrl-C` в терминале.
- Переопределить `DISPLAY` при необходимости: `DISPLAY=:0 scripts/bilireader-run.sh --cef`.

### 1.5 Релизная сборка (если артефактов нет)

```bash
scripts/bilireader-build-linux.sh
```

Скрипт печатает пути и размеры готовых `.AppImage` / `.deb` / `.rpm`.
Требуется ~8 ГиБ свободного места и 25–45 минут на холодном кеше.

## 2. Где взять книги

В репозитории уже лежат два файла — их достаточно для всех проверок ниже:

| Файл | Что внутри | Зачем |
|---|---|---|
| `samples/sample.epub` | EPUB 3, английский текст, 3 главы, оглавление (nav + NCX) | импорт, пагинация, типографика |
| `samples/sample-1251.fb2` | FB2 в кодировке **windows-1251**, русский текст, 3 главы | проверка автоопределения кодировки |

Обе книги короткие (несколько экранов), поэтому листать удобно.

Импорт: на экране библиотеки — кнопка **«+»** (Import) → **Import Books** → выбрать файл.
Альтернатива: перетащить файл в окно приложения. Книга появляется на полке с обложкой-заглушкой.

Свои книги можно положить рядом: `samples/` не является системным каталогом,
приложение читает файл из любого места.

## 3. Проверки

Каждая строка — отдельный сценарий. Если шаг не воспроизводится, фиксируйте номер (B1…B12).

| # | Проверка | Шаги | Ожидаемый результат | Итог |
|---|---|---|---|---|
| **B1** | Импорт EPUB | Библиотека → «+» → Import Books → `samples/sample.epub` | Книга появляется на полке за < 3 с, обложка и название «BiliReader Sample Book», ошибок нет | ☐ |
| **B2** | Открытие и пагинация | Клик по книге → читать 3–4 страницы вперёд | Текст читаемый, поля не обрезаны, номер страницы/процент внизу меняется, заголовок главы виден в начале главы | ☐ |
| **B3** | Листание с клавиатуры | `→` / `Space` / `l` — вперёд, `←` / `Shift+Space` / `h` — назад, 10 раз в каждую сторону; отдельно `PageDown` / `PageUp` | Стрелки и пробел листают по одной странице, без «перескоков» через главу и пустых экранов; `PageDown`/`PageUp` переходят к следующей/предыдущей секции (главе) | ☐ |

## 4. Как сообщить о баге

Пришлите одним сообщением:

1. **Номер проверки** (B1…B12) и что именно сделали — по шагам.
2. **Что ожидали** и **что произошло фактически**.
3. **Скриншот или короткое видео** (для визуальных проблем — обязательно).
4. **Вывод терминала** — запускайте приложение из терминала, чтобы получить stderr:
   ```bash
   ./BiliReader_*.AppImage 2>&1 | tee ~/bilireader-run.log
   ```
   Для dev-режима: `scripts/bilireader-run.sh --cef 2>&1 | tee ~/bilireader-run.log`.
   Приложите последние 50–100 строк — там видно панику Rust/CEF.
5. **Версию и окружение:**
   ```bash
   echo "$(uname -srm)"; echo "DISPLAY=$DISPLAY"; echo "XDG_SESSION_TYPE=$XDG_SESSION_TYPE"
   ./BiliReader_*.AppImage --version 2>/dev/null || true
   ```
   Версия приложения — в Settings → About (или `0.12.16` для этой сборки).
6. Если приложение установлено из `.deb` и падает при старте — добавьте `journalctl`:
   ```bash
   journalctl --user -n 100 --no-pager
   ```

Если книга не открылась — приложите сам файл (или его первые 100 КБ), если это не
приватный документ.

## 5. Что в этот baseline НЕ входит

- Перевод по выделению, словари, TTS, синхронизация, AI-функции (фазы 1+).
- Android/iOS/Windows/macOS — отдельные сборки, отдельные чек-листы.
- Производительность на больших книгах (> 10 МБ) — отдельный замер, фаза 1.

Если что-то из этого не работает — это **не** регрессия baseline.
