# Стратегия релиза BiliReader

Дата: 2026-11-24. Решения согласованы.

## 1. Принятые решения

| Вопрос | Решение |
|---|---|
| Модель перевода | Не входит в бандл. Скачивается при первом запуске |
| Linux-релиз | AppImage на CEF, как в upstream |
| Android | Прямой APK через GitHub Releases, без Google Play |
| Лицензия | AGPL-3.0, исходники публичны |

## 2. Артефакты

| Платформа | Формат | Ожидаемый размер | Что внутри |
|---|---|---|---|
| Linux | AppImage | 250–270 МБ | Приложение + CEF, без модели |
| Linux | deb | 170–190 МБ | То же |
| Android | APK arm64-v8a | 60–90 МБ | Приложение + Rust-ядро, без модели |
| Все | model pack | 1.13 ГБ (Q4_K_M) | Модель Hy-MT2-1.8B |
| Все | dict pack | 30–80 МБ | Словарь en→ru |

Модель и словарь лежат в GitHub Release как отдельные ассеты. Приложение их не содержит.

## 3. Распространение модели

**Первый запуск.** Приложение показывает экран «Загрузить движок перевода» с размером, лицензией и кнопкой. Ничего не качается без согласия.

**Источник.** GitHub Releases этого репозитория. Причина: контроль версий, отсутствие зависимости от Hugging Face, единая точка для Linux и Android.

**Манифест.** Файл `models/manifest.json` в репозитории и в релизе:

```json
{
  "version": 1,
  "models": [
    {
      "id": "hy-mt2-1.8b-q4_k_m",
      "kind": "translation",
      "lang_pair": "en-ru",
      "url": "https://github.com/.../releases/download/v0.1.0/hy-mt2-1.8b-q4_k_m.gguf",
      "size_bytes": 1133080448,
      "sha256": "dc5f44fc...",
      "license": "Apache-2.0",
      "min_ram_mb": 3072
    }
  ]
}
```

**Загрузка.** Потоковая запись в `<models_dir>/.tmp/<id>.part`, заголовок `Range` для докачки, прогресс каждые 256 КБ, проверка sha256, атомарный `rename` после проверки. Обрыв сети не портит установленную модель.

**Хранение по платформам:**

| Платформа | Путь |
|---|---|
| Linux | `~/.local/share/bilireader/models/` |
| Android | `<app files dir>/models/` |
| iOS позже | `Application Support/models/` |

**Тарифы.** Q4_K_M 1.13 ГБ как основной. Позже 2-bit 573 МБ для устройств с 2–3 ГБ RAM, когда будет собрано патченное ядро.

**Offline edition.** Опционально позже: AppImage с моделью внутри, 1.4 ГБ, для закрытых сетей.

## 4. Этап A. Десктоп до состояния «можно дать человеку»

| Шаг | Результат | Критерий приёмки |
|---|---|---|
| A1 | IPC-провайдер завершён и закоммичен | tsc, vitest по затронутым файлам, ручной перевод без сервера |
| A2 | Индекс предложений + режим удержания строки | попадание в строку ≥ 90% на трёх книгах |
| A3 | Менеджер моделей | скачивание, докачка, sha256, удаление, прогресс |
| A4 | Словарный слой L1 | слово переводится < 10 мс, без модели |
| A5 | Сборка AppImage и приёмка | запуск на чистой машине, первый запуск с загрузкой модели |

## 5. Этап B. Сборка Linux

Пайплайн:

1. `pnpm install --frozen-lockfile`
2. `pnpm --filter @readest/readest-app build` (Next.js static export)
3. `TAURI_CEF_CARGO=1 pnpm tauri build --no-sign`
4. Артефакты копируются в `dist/`, считаются sha256, пишется `SHA256SUMS`.
5. `dist/` не коммитится, ассеты уходят в GitHub Release.

Требования к сборочной машине: Rust ≥ 1.95, Node 24, pnpm 11, CEF-кеш 1.8 ГБ, свободно ≥ 8 ГБ.

Проверка перед релизом:

- Запуск на чистой учётной записи без dev-пакетов.
- Первый запуск: загрузка модели, отказ от загрузки, повтор.
- Перевод без сети после загрузки.
- Открытие EPUB и FB2 в windows-1251.

## 6. Этап C. Android APK

**Сборка:**

1. Установить NDK 28, SDK, `cargo-ndk`, цель `aarch64-linux-android`.
2. `pnpm tauri android init` и `pnpm tauri android build --apk`.
3. Только ABI `arm64-v8a`, minSdk 26, target 35.
4. `llama-cpp-sys-2` собирается через NDK с `static-stdcxx`, `ANDROID_NDK` экспортируется явно.

**Работа на телефоне:**

1. Установка APK, первый запуск, экран загрузки модели.
2. Модель качается в приватную папку приложения, разрешения на хранилище не нужны.
3. Перевод считается на CPU: 2–4 потока, контекст 256–512, mmap.
4. Префетч страницы при открытии, чтобы выделение предложения было мгновенным.
5. Сеть нужна только для первой загрузки модели.

**Цели производительности:**

| Метрика | Цель | Как проверяем |
|---|---|---|
| Загрузка модели | ≤ 4 с | лог движка |
| Перевод предложения | ≤ 2 с | замер в приложении |
| RSS | ≤ 2.2 ГБ | `dumpsys meminfo` |
| Размер APK | ≤ 100 МБ | артефакт |

**Ограничения.** Устройства с 2 ГБ RAM не входят в первую версию. Старый WebView ниже 108 не поддерживается, приложение показывает требование обновиться.

## 7. Этап D. Релиз

1. Тег `v0.1.0`, GitHub Release.
2. Ассеты: `BiliReader-0.1.0-x86_64.AppImage`, `.deb`, `BiliReader-0.1.0-arm64.apk`, `hy-mt2-1.8b-q4_k_m.gguf`, `dict-en-ru.sqlite`, `SHA256SUMS`.
3. Скриншоты и гифка в `docs/screenshots/`, гид `docs/guide.md` на русском и английском.
4. Раздел приватности: перевод локальный, текст книги не покидает устройство.
5. AGPL: `NOTICE` со списком изменений относительно Readest, ссылка на исходники.

## 8. Риски

| Риск | Влияние | Митигация |
|---|---|---|
| CEF на слабом Linux | Высокое | floor WebView, тест на старом дистрибутиве |
| RSS 1.9 ГБ на Android | Высокое | контекст 256, mmap, 2-bit позже |
| Скорость 10–20 tok/s | Среднее | префетч, ограничение длины, словарь для слов |
| NDK-сборка llama.cpp | Среднее | спайк до основной работы, фиксация версий |
| Размер репозитория | Низкое | модели только в Release, не в git |
| Диск сборочной машины | Высокое | профиль dev без debug, clean-скрипт, ≥ 8 ГБ перед сборкой |
