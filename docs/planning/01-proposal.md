**Дата:** 2026-11-03

**Основание:** `output/research/01-repos.md`, `02-engines.md`, `03-stack.md`.

## 1. Вердикт в трёх строках

1. Готового продукта «ридер + офлайн-перевод + билингво» не существует. Максимум, что есть: ридеры с **облачным** переводом по выделению.
2. Строим на **Tauri v2 + React/TS + foliate-js (MIT)**. Движок вёрстки берём готовый, ядро перевода пишем на Rust, UI один на все платформы.
3. Перевод делаем **каскадом из трёх уровней**: словарь (мгновенно), маленькая MT для фразы (десятки мс), контекстная MT для предложения (сотни мс, с префетчем страницы).

## 3. Развилка №1: лицензия и база

| Вариант | Срок до телефона | Срок до Linux | Риск | Комментарий |
|---|---|---|---|---|
| **A. Форк Anx Reader** (MIT, Flutter) | **3–4 нед** | ? | Linux + `flutter_inappwebview` не подтверждены. Bus factor = 1 автор | Самый быстрый мобильный MVP. Десктоп под вопросом |
| **B. Tauri v2 + React + foliate-js** (MIT) | 6–8 нед | **2–3 нед** | Больше своего кода | Один код на всё, десктоп first-class, Rust-ядро рядом с UI |
| **C. Форк Readest** (AGPL) | 2–3 нед | 1 нед | **AGPL на весь продукт**, 4 590 файлов | Только если продукт открытый |

**Решение (согласовано 2026-11-03): вариант C, форк Readest.** Продукт открытый, AGPL-3.0 принимается как лицензия проекта.

Почему C, а не B, раз лицензия больше не ограничивает:

- Readest уже даёт **всё окружение**: 6 платформ, FB2 и MD, библиотеку, темы, статистику чтения, попап перевода, словарь Yomitan, синхронизацию, нативную TTS-плагинную обвязку как шаблон моста JS→Kotlin/Swift.
- Архитектура совпадает с рекомендованной: Tauri v2 + React + форк foliate-js. Мы не меняем стек, мы стартуем с 70% готового продукта.
- Слой перевода уже абстрагирован (`src/services/translators/`). Работа сводится к добавлению офлайн-провайдера и Rust-ядра.
- Экономия 6–8 недель против собственной сборки на foliate-js.

**Цена решения:** 4 590 файлов Next.js, тяжёлый онбординг, rebase на upstream при обновлениях, и весь наш код обязан быть AGPL-3.0.

**План B, если форк упрётся:** собственная сборка на `foliate-js` + Tauri (MIT, вариант B). Решение фиксируется после спайка S1 (§10).

## 4. Архитектура

```
┌──────────────────────────── UI (React + TS) ────────────────────────────┐
│  Library │ Reader │ Settings │ Dictionary │ Stats                       │
│  состояние: zustand (лёгкий, без Redux)                                  │
└───────────────┬──────────────────────────────────┬──────────────────────┘
                │ Tauri IPC (commands/events)      │ postMessage
┌───────────────▼──────────────┐      ┌────────────▼──────────────────────┐
│  Rust core (src-tauri)       │      │  foliate-js в iframe/WebView      │
│  ├ models: manager, download │      │  ├ paginator.js  (CSS columns)    │
│  ├ mt: trait Engine          │      │  ├ sentence index (offsets)       │
│  │   ├ DictionaryEngine      │      │  ├ long-press / line-follow       │
│  │   ├ MarianEngine (ONNX)   │      │  └ overlay: подсветка, попап      │
│  │   └ LlamaEngine (GGUF)    │      └───────────────────────────────────┘
│  ├ queue: BinaryHeap+abort   │
│  ├ cache: SQLite (sha256)    │
│  └ store: books, progress    │
└──────────────┬───────────────┘
               │ FFI
      ┌────────▼─────────┐
      │ llama.cpp / ORT  │  (Android NDK, iOS, x86_64, arm64)
      └──────────────────┘
```

**Почему так:**

- **Rust-ядро** держит модель в памяти (mmap), отдаёт перевод по IPC, живёт вне UI-потока. Отмена генерации по атомарному флагу, а не убийством потока.
- **foliate-js внутри WebView** даёт бесплатно то, что дороже всего писать: переносы, сноски, картинки, таблицы, `break-inside`, RTL.
- **Интерфейс провайдера перевода** оставляет дверь для сети: LibreTranslate, DeepL, «свой сервер» для web-версии и для слабых устройств. Это не костыль, это требование к дизайну.

## 5. Движок перевода: каскад

### 5.1 Схема

| Уровень | Что переводим | Движок | Латентность | Размер |
|---|---|---|---|---|
| **L1** | 1 слово | словарь kaikki/Wiktionary в SQLite + лемматизация | **< 10 мс** | 30–80 МБ на пару |
| **L2** | 2–6 слов | OPUS-MT int8 через ONNX Runtime Mobile, либо Bergamot | **40–150 мс** | 34–135 МБ на пару |
| **L3** | предложение и больше | Hy-MT2-1.8B, 2-bit GGUF, llama.cpp | **0.4–1.5 с** | 573 МБ одна на все языки |

Слово через словарь, а не через MT, это не компромисс. Это ещё и педагогически правильнее: пользователь видит список значений с частью речи, а не одну кривую строку.

### 5.2 Модели, обоснование выбора

| Модель | Размер | Лицензия | Почему да / почему нет |
|---|---|---|---|
| **Hy-MT2-1.8B** (2026-05) | 440 МБ / 573 МБ / 1.13 ГБ | **Apache-2.0** | Да. Замер на ARM: prefill 223 мс, 49.6 tok/s, RSS 1.1 ГБ |
| Hy-MT1.5 из задания | 440 МБ | **Tencent Community: запрет EU/UK/KR** | **Нет. Юридический блокер** |
| **OPUS-MT** (Marian 77M) | 79–135 МБ на пару | CC-BY-4.0 / Apache-2.0 | Да. Единственный класс, попадающий в «мгновенно» |
| **Bergamot** | 34 МБ на направление | MPL-2.0 | Да, если нужен минимум памяти. Минус: de/fr/es→ru только через пивот en |
| NLLB-200-600M | 600 МБ | CC-BY-**NC** | Нет. Некоммерческая |
| MADLAD-400-3B / SeamlessM4T | 0.9–2 ГБ | Apache / NC | Нет. Не влезает в бюджет RAM |
| Qwen3-1.7B / EuroLLM | 1–1.4 ГБ | Apache | Нет. Не MT-тюн, ru у EuroLLM отсутствует |
| **Whisper** | 75–142 МБ | MIT | **Не нужен для перевода.** Это распознавание речи. Для озвучки нужен Piper |

### 5.3 Как достигается «мгновенный отклик»

1. **Кэш на всё.** Ключ `sha256(normalized(text) + src + dst + level + model)`. Повторное нажатие = 0 мс, попадание в кэш видно мгновенно.
2. **Префетч страницы.** Открыл страницу, ядро в фоне переводит её предложения через L3. Тап по предложению отдаёт готовое.
3. **Двухступенчатая выдача.** Сначала L2 за 40–150 мс, через 0.5 с замена на уточнённый L3, если он лучше.
4. **Тёплая модель.** Не грузим и не выгружаем на каждый тап. На Android держим Foreground Service, иначе ОС убьёт процесс.
5. **Очередь с приоритетами и отменой.** Immediate (под пальцем) > CurrentPage > Adjacent > Background. Задачи старого поколения отменяются до инференса.

### 5.4 Менеджер моделей

В APK кладём только словарь и UI, около 30–50 МБ. Модели докачиваются по выбору пары языков. Play-лимит 200 МБ на base, значит иного пути нет. Пользователь видит: «en→ru: словарь 45 МБ, быстрый движок 135 МБ, качественный 573 МБ».

## 6. Чтение и пагинация

**Механика.** Раздел книги раскладывается в CSS multi-column. Iframe растягивается на `pageCount * size`. Контейнер скроллится ровно на одну колонку. Смена шрифта, кегля, интерлиньяжа, полей или размера окна не перезагружает DOM, а вызывает `columnize() → expand() → scrollToAnchor(anchorRange)`. Номер страницы пересчитывается, место чтения сохраняется.

**Правила, без которых это разваливается на слабом железе:**

- Резать книгу на разделы **≤ 30 КБ**. Для TXT/MD/FB2 это синтетические разделы, иначе один reflow на 200 КБ даст сотни мс.
- Смена настроек с debounce 150–250 мс и индикатором «пересчёт».
- Кодировки FB2 (windows-1251, koi8-r) читать из XML-декларации через `TextDecoder`.
- Политика совместимости: WebView ≥ 108, iOS ≥ 15.4. Ниже — детект и fallback в режим прокрутки.

**Навигация:** свайп влево/вправо (тап по краям как альтернатива), стрелки и колесо на десктопе, настраиваемые тап-зоны. Направление свайпа выносим в настройку, вертикальный режим тоже.

**Прогресс:** `(Σ size разделов до текущего + fraction * size текущего) / Σ size`. Линия внизу, перпендикулярная метка, подпись в процентах. Тап по линии открывает переход по главам.

**Темы:** light / dark / sepia плюс токены на будущее: `--bg`, `--fg`, `--font-family`, `--font-size`, `--line-height`, `--margin`. Кастомизация сводится к редактированию токенов, а не к новой вёрстке.

## 7. Билингво-режим и sentence index

**Почему offset, а не CFI.** CFI привязан к структуре EPUB и ломается на FB2/TXT/MD. Перепагинация не меняет текст, поэтому глобальные смещения в символах остаются валидными.

**Построение индекса раздела** (один раз, кэш в памяти + SQLite, 1–5 мс на 30 КБ):

1. `TreeWalker` по текстовым узлам, пропуская `script/style` и наши оверлеи.
2. Конкатенация в канонический текст, таблица `{node, start, end}`.
3. `Intl.Segmenter(granularity:'sentence')`.
4. Пост-обработка обязательна: склейка сокращений (`т. е.`, `г.`, `Mr.`, `e.g.`), инициалов, слишком коротких сегментов, запрет склейки через `<br>`.
5. `blockId` подъёмом до block-level предка.

**Long-press и «линейка»:**

1. `pointerdown` → таймер 350–450 мс + допуск движения 8 px, иначе это свайп.
2. Точка → `caretPositionFromPoint` → глобальный offset → бинарный поиск предложения.
3. `getClientRects()` → группировка по `top` ±2 px → бокс на каждую строку → растяжка до ширины колонки.
4. Подсветка рисуется в оверлее поверх iframe, `pointer-events: none`. Внутрь книги не лезем, иначе ломаются CFI и выделение.
5. Попап живёт в host-DOM вне iframe, `translate(-50%,-100%)` над первой строкой, при нехватке места под последней.

**Плавное сползание пальца:** при `|dy| > 0.8 * lineHeight` активное предложение меняется, debounce 120 мс, префетч `[i-1, i, i+1]`, generation-токен отменяет старое. На границе раздела подгружается следующий раздел и его индекс.

## 8. Библиотека и задел под обучение

Книги не копируем, храним ссылку на файл: SAF tree URI на Android, security-scoped URL на iOS, путь на десктопе.

```sql
books(id, uri, format, title, author, lang_src, lang_dst,
      cover_path, size_bytes, hash, added_at, last_opened_at)
sections(book_id, idx, href, byte_size, text_hash)
progress(book_id, section_idx, char_offset, fraction, updated_at)
translations(key PK, src_lang, dst_lang, level, model_id,
      source_text, target_text, created_at, hit_count)
vocab(id, book_id, lemma, surface, lang, context_sentence,
      translation, status, added_at, due_at, ease)      -- фаза обучения
reading_sessions(id, book_id, started_at, ended_at,
      pages, chars, translation_count)                   -- метрики
models(id, kind, lang_pair, path, size_bytes, sha256, installed_at)
settings(key, value)
```

`vocab` и `reading_sessions` создаём сразу, даже если UI для них появится позже. Иначе потом миграции.

## 9. Что входит в первую версию, а что нет

**Входит:**

- Библиотека, импорт epub / fb2 / txt / md
- Пагинация с настройкой шрифта, кегля, интерлиньяжа, полей
- Темы light / dark / sepia
- Свайпы, стрелки, тап-зоны, прогресс-бар
- Выделение слова → словарная карточка
- Выделение предложения → перевод с контекстом
- Кэш и префетч
- Менеджер моделей

**Не входит в первую версию:**

- PDF и OCR
- Синхронизация между устройствами
- SRS и тренажёр (только схема БД)
- TTS
- iOS-сборка
- Облачный перевод как основной режим

Итог фазы: подтверждённая база, подтверждённая латентность, зафиксированный бюджет RAM.

### Фаза 1. MVP на Linux, 2–3 недели

Форк Readest, сборка под Linux, офлайн-провайдер перевода с ядром на Rust, L1 и L2, кэш и префетч. Библиотека, импорт, пагинация, темы и прогресс уже есть в базе.

### Фаза 2. Билингво и Android, 4–5 недель

Режим удержания строки, префетч соседних предложений, L3, сборка Android, уровни моделей по RAM, детект WebView.

### Фаза 3. Обучение и остальные платформы, 5–7 недель

Карточки слов, SRS, экспорт в Anki, статистика чтения, Windows/macOS, TTS через Piper, iOS.

Оценки для одного разработчика с ИИ-ассистентом. Спайки делаются до плана, поэтому вилка по срокам закроется после фазы 0.

## 12. Главные риски

| Риск | Влияние | Митигация |
|---|---|---|
| 1.25/2-bit GGUF требуют патченного llama.cpp (STQ PR не влит) | Высокое | Вендорим форк с пином коммита, fallback Q4_K_M 1.13 ГБ |
| WebView < 108 на старых Android | Высокое | Floor 108, детект, fallback в режим прокрутки |
| RSS L3 около 1.1 ГБ на устройствах с 2 ГБ | Высокое | Режим «только L1+L2», выбор модели по RAM |
| FB2 в foliate-js слабее crengine | Среднее | Тест-корпус 10–15 реальных FB2, дифф против KOReader |
| Латентность цикла JS→Rust→MT→JS | Высокое | Батчинг, отмена, кэш, прогрев, замер на целевом устройстве |
| Bus factor у MIT-баз | Среднее | Пиннинг тега, foliate-js как submodule, свои тесты рендера |
| Pandoc/Calibre как конвертер | Низкое | Только для импорта, внешним процессом, не в рантайме |

## 13. Чем продукт отличается

- Единственный ридер, где перевод **работает офлайн и стоит ноль за запрос**.
- Единственный, где перевод **адаптирован под предложение**, а не под слово.
- Режим «линейка»: палец ведёт по строкам, перевод появляется над строкой с опережением на строку вперёд и назад.
- Словарь и MT в одном попапе: сначала значения, потом связный перевод.
- Десктоп и телефон на одном коде, без Electron.
