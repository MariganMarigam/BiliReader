# Lean workflow

The fork's disk budget is tight (the root volume runs at 95–99 %), and a release
bundle costs ~6 GB plus ~1.8 GB of CEF download cache. So: iterate in dev mode,
package only at checkpoints, and clean up after.

## Default mode — dev, never bundles

```sh
scripts/bilireader-run.sh            # pnpm tauri dev + Next.js, hot reload
DISPLAY=:0 scripts/bilireader-run.sh # from a non-graphical shell
```

- Edit → save → the UI hot-reloads. Nothing is packaged, no AppImage is produced.
- The first run compiles the Rust backend (10–20 min); later runs start in
  seconds.
- On Linux both `dev` and `build` run the **CEF** runtime
  (`apps/readest-app/scripts/tauri.mjs` adds `--features cef
  --no-default-features`), not WebKitGTK. The WebKitGTK/wry runtime is only used
  by mobile commands and `scripts/test-tauri.sh`.
- Stop with Ctrl-C. Logs go to the terminal; nothing is written outside
  `target/debug`.

## When a release build is allowed

Only at a checkpoint — a commit you actually want to hand out (release tag,
nightly, "does the packaged app work" verification):

```sh
df -h /                                  # must show >= 8 GB free
scripts/bilireader-build-linux.sh        # 25–45 min, ~6 GB of target/release
scripts/bilireader-build-linux.sh --bundles appimage
```

Do **not** run it per iteration or "just to check". The script exits with
`ERROR: need at least 8 GB free` before it touches anything if the volume is
too full; run `scripts/bilireader-clean.sh --yes` first.

## Where artifacts go

- Bundles land in `target/release/bundle/{appimage,deb,rpm}/` and are wiped by
  the next clean.
- Keep the one you care about in `dist/`:

  ```sh
  cp target/release/bundle/appimage/BiliReader_<version>_amd64.AppImage \
     dist/BiliReader-<version>-x86_64.AppImage
  sha256sum dist/BiliReader-<version>-x86_64.AppImage
  ```

- `dist/` is git-ignored via `.git/info/exclude` (not `.gitignore`): artifacts
  never enter the repository, but they survive `git status` noise-free.

## What can be deleted

```sh
scripts/bilireader-clean.sh         # dry run: prints paths and freed space
scripts/bilireader-clean.sh --yes   # actually delete, then prints df -h /
```

| Path                   | Typical size | Safe to delete | Regenerated by                       |
| ---------------------- | ------------ | -------------- | ------------------------------------ |
| `target/release/`      | 5.8 GB       | yes            | `scripts/bilireader-build-linux.sh`  |
| `target/debug/`        | 8 GB         | yes            | `scripts/bilireader-run.sh`          |
| `~/.cache/tauri-cef/`  | 1.8 GB       | yes            | next CEF command (re-downloads CEF)  |
| `dist/`                | 255 MB       | **no**         | only by re-running the build         |
| `~/.cargo/`            | 1.2 GB       | **no**         | would re-download the whole registry |
| `~/.cache/uv/`         | 9.2 GB       | **no**         | not ours — other projects use it     |
| `~/.cache/pip/`        | 5.4 GB       | **no**         | not ours — other projects use it     |
| `node_modules/`, `.git/` | —          | **no**         | reinstall / unrecoverable            |

The clean script refuses those protected paths explicitly (see its `forbidden`
list) and never deletes outside `target/{release,debug}` and
`~/.cache/tauri-cef`.

Cost of cleaning `~/.cache/tauri-cef`: the next release build downloads the CEF
distribution again (~150 MB) and recompiles `libcef_dll_wrapper`. That is cheap
compared with the build itself, so clean it whenever you are done packaging.

`target/debug/` is the expensive one to lose: a cold `pnpm tauri dev` compiles
~1250 crates including the CEF wrapper and takes 20+ minutes here. Delete it
when the disk is full, not after every session.

## Disk rule

- **< 8 GB free** → no release build. The build script refuses to start.
- **≥ 10 GB free** → comfortable: CEF build plus one bundle fits without
  cleanup mid-run.
- Check with `df -h /`; the clean script prints it before and after.
