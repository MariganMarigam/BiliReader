# Lean workflow

The fork's disk budget is tight (the root volume runs at 95–99 %), and a release
bundle costs ~6 GB plus ~1.8 GB of CEF download cache. So: iterate in dev mode,
package only at checkpoints, and clean up after.

## Three dev cycles — pick the cheapest one that answers your question

`scripts/bilireader-run.sh` has three modes. The default is the cheap one; the
expensive ones are opt-in.

| Mode        | Command                          | Start                  | Disk         | What works                                                                                 |
| ----------- | -------------------------------- | ---------------------- | ------------ | ------------------------------------------------------------------------------------------ |
| **web**     | `scripts/bilireader-run.sh`      | 5–15 s                 | ~0           | Next.js in a browser (`http://localhost:3000`): library, reader, styles, sync scaffolding. |
| **desktop** | `scripts/bilireader-run.sh --desktop` | 10–15 min cold, 10–60 s warm | 2–3 GB | Tauri window on WebKitGTK (wry). Full IPC, native dialogs, TTS.                            |
| **cef**     | `scripts/bilireader-run.sh --cef` | 20+ min cold, then fast | ~8 GB       | The old default: CEF runtime, native page-curl cover, CDP debugging.                       |

### web — the default cycle

```sh
scripts/bilireader-run.sh             # cd apps/readest-app && pnpm dev-web
scripts/bilireader-run.sh --web 3001  # extra args are forwarded to `next dev`
```

- No Rust, no `target/`, no CEF: 5–15 s from command to a served page, disk cost
  nil. Edit → save → browser hot-reloads.
- Missing here: Tauri IPC (filesystem plugin, native dialogs), TTS, the updater,
  and the native page-curl cover. Anything purely UI/reader/styling is testable.
- If `:3000` is taken, Next.js picks the next free port and prints it.

### desktop — when you need the real window

```sh
scripts/bilireader-run.sh --desktop  # CARGO_PROFILE_DEV_DEBUG=0 pnpm exec tauri dev
```

- Uses WebKitGTK/wry (default features), **not** CEF, so no `libcef_dll_wrapper`
  compile and no 1.8 GB CEF download.
- `CARGO_PROFILE_DEV_DEBUG=0` drops debuginfo: that alone is the difference
  between ~2–3 GB and ~8 GB of `target/debug`. Trade-off: GDB backtraces lose
  line numbers; drop the env var temporarily if you are debugging Rust.
- Broken here: the native page-curl cover effect and CDP-based debugging.

### cef — only when CEF behaviour is the question

```sh
scripts/bilireader-run.sh --cef      # pnpm tauri dev via scripts/tauri.mjs
DISPLAY=:0 scripts/bilireader-run.sh --cef   # from a non-graphical shell
```

- `apps/readest-app/scripts/tauri.mjs` adds `--features cef --no-default-features`
  for Linux dev and build alike. Needs `libclang`, `LIBCLANG_PATH`, and X11.
- Cold cost: 20+ minutes and ~8 GB of `target/debug`. Reserve it for work that
  genuinely touches CEF (cover animation, CDP, packaging parity).

In every mode: nothing is packaged, no AppImage is produced, stop with Ctrl-C,
logs go to the terminal.

## Release bundles: only at a checkpoint

**Rule: build bundles only at a checkpoint**, never per iteration and never
"just to check". A checkpoint is a commit you actually want to hand out (release
tag, nightly, "does the packaged app work" verification). Everything before that
checkpoint happens in one of the three dev cycles above.

```sh
df -h /                                  # must show >= 8 GB free
scripts/bilireader-build-linux.sh        # 25–45 min, ~6 GB of target/release
scripts/bilireader-build-linux.sh --bundles appimage
```

Do **not** run it per iteration or "just to check". The script exits with
`ERROR: need at least 8 GB free` before it touches anything if the volume is
too full; run `scripts/bilireader-clean.sh --yes` first.

## Where artifacts go

- Bundles land in `target/release/bundle/{appimage,deb,rpm}/` and are wiped by
  the next clean.
- Keep the one you care about in `dist/`:

  ```sh
  cp target/release/bundle/appimage/BiliReader_<version>_amd64.AppImage \
     dist/BiliReader-<version>-x86_64.AppImage
  sha256sum dist/BiliReader-<version>-x86_64.AppImage
  ```

- `dist/` is git-ignored via `.git/info/exclude` (not `.gitignore`): artifacts
  never enter the repository, but they survive `git status` noise-free.

## What can be deleted

```sh
scripts/bilireader-clean.sh         # dry run: prints paths and freed space
scripts/bilireader-clean.sh --yes   # actually delete, then prints df -h /
```

| Path                   | Typical size | Safe to delete | Regenerated by                       |
| ---------------------- | ------------ | -------------- | ------------------------------------ |
| `target/release/`      | 5.8 GB       | yes            | `scripts/bilireader-build-linux.sh`  |
| `target/debug/`        | 2–3 GB (desktop) / ~8 GB (cef) | yes | `scripts/bilireader-run.sh --desktop` (or `--cef`) |
| `~/.cache/tauri-cef/`  | 1.8 GB       | yes            | next CEF command (re-downloads CEF)  |
| `dist/`                | 255 MB       | **no**         | only by re-running the build         |
| `~/.cargo/`            | 1.2 GB       | **no**         | would re-download the whole registry |
| `~/.cache/uv/`         | 9.2 GB       | **no**         | not ours — other projects use it     |
| `~/.cache/pip/`        | 5.4 GB       | **no**         | not ours — other projects use it     |
| `node_modules/`, `.git/` | —          | **no**         | reinstall / unrecoverable            |

The clean script refuses those protected paths explicitly (see its `forbidden`
list) and never deletes outside `target/{release,debug}` and
`~/.cache/tauri-cef`.

Cost of cleaning `~/.cache/tauri-cef`: the next release build downloads the CEF
distribution again (~150 MB) and recompiles `libcef_dll_wrapper`. That is cheap
compared with the build itself, so clean it whenever you are done packaging.

`target/debug/` is the expensive one to lose: a cold `--cef` run compiles ~1250
crates including the CEF wrapper and takes 20+ minutes here; `--desktop` compiles
a smaller wry-only tree in 10–15 minutes and 2–3 GB. Both are rebuilt by the same
script, so delete `target/` when the disk is full, not after every session — and
prefer staying in web mode so neither exists in the first place.

## Local MT server

Offline EN→RU translation for quality checks takes ~1.2 GB under
`~/.local/share/bilireader/`; it is not build output and the clean script leaves
it alone. Install, run and removal: [local-mt-server.md](local-mt-server.md).

## Disk rule

- **< 8 GB free** → no release build. The build script refuses to start.
- **≥ 10 GB free** → comfortable: CEF build plus one bundle fits without
  cleanup mid-run.
- Check with `df -h /`; the clean script prints it before and after.
