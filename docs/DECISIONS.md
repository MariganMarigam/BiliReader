## ADR-001 — Форк Readest и AGPL-3.0

**Контекст.** Нужна база с CSS-пагинацией, EPUB/FB2 и абстракцией переводчиков.
Кандидаты: Anx Reader (MIT, Flutter), собственная сборка на `foliate-js`,
Readest (AGPL-3.0, Tauri + React). Readest даёт ~70 % готового продукта, но его
лицензия распространяется на весь форк.

**Решение.** Форк `readest/readest`; продукт открытый, весь код форка —
AGPL-3.0, исходники публикуются в `MariganMarigam/BiliReader`.

**Следствия.** Нельзя закрыть код или раздавать бинарники без исходников;
нужен `NOTICE` с изменениями относительно upstream. Взамен — готовое
окружение, шесть платформ и совпадающий с исследованием стек. Anx Reader
отвергнут: Flutter требует своего текстового layout, Linux-десктоп не
подтверждён.

## ADR-002 — Tauri v2 + React вместо Flutter

**Контекст.** Ключевое требование — перевёрстка EPUB/FB2 под шрифт, кегль,
поля и экран. Flutter не имеет CSS-движка: пагинацию, переносы, сноски и
таблицы пришлось бы писать самим. Tauri использует WebView и CSS columns.

**Решение.** Tauri v2 + Next.js 16 + React + zustand; книга рендерится
`foliate-js` внутри WebView, Rust-ядро рядом с UI.

**Следствия.** Один код на desktop/web/mobile, CSS-пагинация «из коробки»,
нативный инференс через Rust. Цена — зависимость от системного WebView на
Android (floor ~108) и шершавый мобильный тулчейн Tauri.

## ADR-003 — CEF на Linux

**Контекст.** Upstream Readest собирает Linux-релизы на CEF-рантайме из своей
ветки Tauri, а не на WebKitGTK. Разные WebView дают разное поведение
пагинации и шрифтов.

**Решение.** На Linux `pnpm tauri dev|build` идут через CEF-CLI и
`--config src-tauri/.cargo/cef.toml`; Windows и macOS остаются на wry.

**Следствия.** Паритет с upstream и предсказуемый Chromium. Цена: `libcef.so`
~256 МиБ в бандле, X11 вместо Wayland, сборка требует cmake/ninja/libclang.
Android CEF не использует.

## ADR-004 — `llama-cpp-2` вместо ручного FFI

**Контекст.** План Фазы 1 предполагал вендорить `llama.cpp` и писать FFI
вручную. Это даёт контроль, но требует сопровождать биндинги, сборочные
флаги и ABI на трёх платформах.

**Решение.** Крейт `llama-cpp-2` 0.1.161: `llama-cpp-sys-2` вендорит C++
`8642541b…` (v0.8.0) и готовые биндинги; на Linux/Android линкуется
`static-stdcxx`. Версия caret, точная — в `Cargo.lock`.

**Следствия.** Нет своего `unsafe`-слоя; обновление — смена версии крейта.
Caret оставляет возможность `[patch.crates-io]` на форк STQ для 1.25-bit.
Цена — долгая сборка C++ и зависимость от качества wrapper-крейта.

## ADR-005 — Hy-MT2 вместо Hy-MT1.5

**Контекст.** В задании была Hy-MT1.5-1.8B, но её лицензия исключает EU, UK и
South Korea, требует отдельного договора при >100 млн MAU и запрещает
использовать вывод для обучения других моделей. Публикация в сторах — это
дистрибуция в EU/UK.

**Решение.** Hy-MT2-1.8B под Apache-2.0, квант Q4_K_M (1.13 ГБ).

**Следствия.** Юридический блокер снят. Качество en→ru независимо не
подтверждено; 2-bit и 1.25-bit варианты не используются, пока upstream
`llama.cpp` не содержит нужных ядер.

## ADR-006 — Hugging Face как источник модели

**Контекст.** Модель весит 1.13 ГБ. Нужен стабильный URL, поддержка `Range`
для докачки и неизменяемые байты.

**Решение.** Первый (и пока единственный) URL — Hugging Face с закреплённой
ревизией `a0c709d9…`, а не `main`. `urls` — массив: второй источник можно
добавить без смены схемы.

**Следствия.** Ревизия гарантирует, что SHA-256 не разойдётся. Failover
перебирает URL по порядку; ошибка сети/размера/чексуммы переходит к
следующему, отмена и диск — нет. GitHub Release как зеркало запланирован, но
не опубликован; добавлять его в манифест до публикации нельзя.

## ADR-007 — FreeDict CC BY-SA для словаря

**Контекст.** Нужен офлайн-словарь EN–RU с открытой лицензией, без сети и без
LLM. FreeDict+WikDict даёт 62 181 статью, ~6.5 МБ в StarDict/DictZip.

**Решение.** Встроить FreeDict eng-rus 2025.11.23 (CC BY-SA 3.0) в
`public/dicts/freedict-eng-rus/`; читать через `StarDictReader`, тело —
DictZip.

**Следствия.** Copyleft распространяется на данные и их адаптации, но не на
код приложения, который их читает. Нужны `LICENSE` и `ATTRIBUTION.md`;
изменённый словарь обязан остаться CC BY-SA. Пользователь может импортировать
свои StarDict-словари тем же ридером.

## ADR-008 — Каскад «словарь → MT»

**Контекст.** LLM плохо отвечает на одно слово: нет части речи, списка
значений и леммы, латентность 0.4–1.5 с. Словарь отвечает за единицы
миллисекунд. Для фраз задумывался быстрый L2 (OPUS-MT/Bergamot), для
предложений — L3.

**Решение.** L1: одно слово → точная форма → лемма → карточка. Промах или
фраза → существующий путь переводчика. L2 в 0.1.0 не реализован: фраза сразу
идёт в L3.

**Следствия.** Слово никогда не ждёт LLM; предложение получает контекст.
Каскад остаётся расширяемым: `Engine`/`Level` уже есть в Rust, добавление L2
не меняет контракт провайдера.

## ADR-009 — Offsets вместо CFI

**Контекст.** CFI привязан к структуре EPUB и дорожает/ломается на FB2, TXT и
MD. Перепагинация не должна сбрасывать якоря предложений и попапа.

**Решение.** Канонический текст раздела + UTF-16 offsets; `text-index.js`
хранит `(node, start, end)`, границы предложений и хеш текста. Обратное
преобразование — `rangeFromOffsets`.

**Следствия.** Перепагинация не инвалидирует индекс, потому что DOM-текст не
меняется. Индекс пересобирается при выгрузке/перезагрузке раздела (1–5 мс на
30 КБ) и кэшируется по хешу. CFI остаётся только для закладок/аннотаций
upstream, не для предложений.

## ADR-010 — Порог склейки предложений 16 символов

**Контекст.** План предлагал `SEG_MIN_CHARS = 40`, чтобы склеивать обрывки
вроде «Да.». Проверка на корпусе показала: 40 склеивает полноценные
предложения длиной 19–23 символа и противоречит приёмочным кейсам A2.

**Решение.** `SEG_MIN_CHARS = 16` в `packages/foliate-js/text-index.js`.
Сегмент короче 16 символов сливается со следующим, если между ними нет
жёсткого разрыва (`<br>`, блок).

**Следствия.** «Да.» и «Нет.» склеиваются, короткие законченные предложения
остаются отдельными. Порог — константа движка; менять её можно только с
пересмотром тестов сегментации.

## ADR-011 — Профиль dev без debuginfo

**Контекст.** Dev-сборка компилирует вендоренный C++ `llama.cpp` и ~1250
крейтов. Полный DWARF раздувает `target/debug` до десятков гигабайт, а на
корневом разделе бывает 95–99 % занято.

**Решение.** В корневом `Cargo.toml`: `[profile.dev] debug = 0`,
`incremental = false`. Переменная `CARGO_PROFILE_DEV_DEBUG` не нужна.

**Следствия.** Сборка и диск заметно меньше, инкрементальный кэш отключён.
Backtrace без номеров строк; для отладки конкретного крейта можно временно
включить debug точечно или собрать release.

## ADR-012 — Модель отдельно от бандла

**Контекст.** GGUF весит 1.13 ГБ. Если положить его в AppImage/APK, бандл
становится неприемлемо большим, а обновление приложения тянет модель заново.
Play ограничивает base APK 200 МБ.

**Решение.** В бандл входят только код, словарь и шрифты. Модель скачивается
из Settings → Language → Offline engine по манифесту, с проверкой размера и
SHA-256, докачкой `Range` и удалением.

**Следствия.** Первый запуск перевода требует интернета и ~1.13 ГБ. Нет
фоновой автозагрузки: пользователь нажимает Download. Смена модели — правка
манифеста и пересборка, потому что манифест компилируется в бандл.

## ADR-013 — Прямой APK без Google Play

**Контекст.** AGPL, размер модели, ограничение Play на base APK и ревью
затрудняют публикацию. Приложение всё равно требует ручной установки модели.

**Решение.** Android-релиз — APK `arm64-v8a` через GitHub Releases, без Play.
Подпись — локальный keystore, обновления вручную.

**Следствия.** Нет Play Services, биллинга и автообновлений; пользователь
видит предупреждение sideload. Зато нет ревью и лимита 200 МБ, а исходники и
APK лежат в одном месте. Android-сборка в 0.1.0 ещё не проверялась.
